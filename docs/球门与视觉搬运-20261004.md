## 球门与行走带球

门框按两根立柱与顶部横梁识别，不用颜色。门框唯一且连续稳定5帧才参与控制。头部跟踪球，腹部接住后头部回正129看门；先转向门中心，再横移使腹部球中心落在画面中间的42%至58%带内，对齐后前进一轮，重新观察后再决定下一轮。不发送 RIGHT_BALL。

```bash
cd /home/yuting/robot_env
bash setup_head_pwm.sh start
ROBOT_HEAD_PWM_BACKEND=pigpio \
ROBOT_CAMERA_FOURCC=MJPG \
ROBOT_KICK_HEAD_DEVICE=/dev/v4l/by-id/usb-lihappe8_Corp._USB_2.0_Camera-video-index0 \
ROBOT_KICK_BELLY_DEVICE=0 \
./venv/bin/python main.py handover --run --actions
```

先去掉 --actions 查看球门框和球；预览仍控制头部舵机。丢失球门或多个门框时，腹部阶段暂停身体动作。2026-10-05 回退后，丢球仅先视觉重找、再最多3次低头，不执行旋转或搜索前进；搜索耗尽按原版停止。保留30次身体动作、120秒上限，Q 在动作间退出。底层动作同步执行，Q 不是即时硬件急停。

门框规则参考用户提供的通知内嵌足球场示意图：箱体式球门的正面开口。没有使用不确定的实际尺寸。纯形状无法保证区分窗口和球门；严重斜视、遮挡或门口不完整时可能不识别。各相机画面中心对齐是二维近似，需要现场确认安装朝向和转向效果。尚未实现进球判断，球消失不能当作成功。

该通知明确要求明显踢球动作，行走带入不计成绩。按用户选择，本入口继续用于行走带球调试；比赛时需要另行恢复单次踢球。

## 颜色方块搬运

先按启动提示选择颜色 red红、green绿、blue蓝、yellow黄、pink粉，并输入目的地二维码完整内容。参数省略时在终端输入，也可通过 --color 与 --target-qr 传入。二维码只作为目的地标识，不执行二维码文本里的动作或网址。

颜色先排除其他颜色；再通过凸四至六边形和尺寸筛选方块可见外观。只有一个指定颜色方块且稳定5帧时才移动，同色多目标时暂停。二维外观不是三维立方体证明，相似颜色的矩形图案仍可能误检，先看预览确认。

先启动预览，以下 blue 与 DROP_1 是示例，需要换成现场目标：

```bash
cd /home/yuting/robot_env
bash setup_head_pwm.sh start
ROBOT_HEAD_PWM_BACKEND=pigpio \
ROBOT_CAMERA_FOURCC=MJPG \
ROBOT_KICK_HEAD_DEVICE=/dev/v4l/by-id/usb-lihappe8_Corp._USB_2.0_Camera-video-index0 \
./venv/bin/python main.py carry --mode visual --run --preview
```

预览会将头部设为129，但不开身体串口、不发站立或搬运动作。若暂时不知道二维码内容，可以先输入“待定”，预览会在终端打印解码成功的各二维码内容；确认后退出并重启，输入实际目的地。

抱取和放下位置不能根据示意图猜：

1. 机器人保持与实际运行相同的标准站姿，头部保持129。把方块放在已验证可抱起的位置，确认绿框准确后按 H，保存当前方块位置和大小。
2. 把目标二维码置于已验证可放下的位置，机器人仍保持相同姿态，确认二维码内容匹配后按 D，保存当前二维码位置和大小。这里保存的是机器人放下时看到的二维码位置，不一定是物块覆盖二维码的位置。
3. H/D 可分别保存；两个位置都有后才可启用 --actions。修改目标二维码、相机视图、画面尺寸或头位后，需要重新标定。新文件是 config/carry_reference.json，原头部和踢球标定不会被覆盖。

实际运行示例：

```bash
ROBOT_HEAD_PWM_BACKEND=pigpio \
ROBOT_CAMERA_FOURCC=MJPG \
ROBOT_KICK_HEAD_DEVICE=/dev/v4l/by-id/usb-lihappe8_Corp._USB_2.0_Camera-video-index0 \
./venv/bin/python main.py carry --mode visual --run --actions --color blue --target-qr 'DROP_1'
```

身体串口沿用固定 by-path。动作模式握手后发送一次 STAND，再将头部设为129。先横移/前进靠近方块，标定位置稳定确认后执行 HOLD_BOX；随后精确寻找指定二维码，用 LEFT_HOLDBOX、RIGHT_HOLDBOX 转向，用 UP_HOLDBOX 前进，标定放下位置稳定确认后只执行一次 DOWN_BOX。每次动作后读新画面重新确认。动作发送失败立即退出，不自动重复抱起或放下。

当前没有全场定位、绕障或主动扫描地图；目标方块或目标二维码不在视野内时保持等待，不盲走。画面过近时停止，最多40次身体动作、180秒。实际是否抱住物块、是否放到正确位置尚无传感器验证，程序仅报告动作完成。Q 在当前动作完成后生效。

仅新视觉入口使用这套功能；原语音搬运和 main.py carry --mode fixed 仍是旧固定动作，不应当作自主搬运。
