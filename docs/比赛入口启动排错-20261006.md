## 本次确认的故障与修复

1. 树莓派 `Picamera2.global_camera_info()` 只返回一只USB相机，`Num: 0`，没有OV5647/CSI。原腹部编号0实际打开了头部正在使用的USB，因此报设备占用。改成1不能恢复缺失的相机。`hardware/roboteye.py` 已在打开CSI前检查列表位置和相机身份，拒绝USB或不存在的编号。
2. 新人脸入口初始化姓名SDK前，没有恢复 `face.eim` 的执行权限。`app/competition_identity.py` 现沿用旧入口的做法，只补文件所有者的执行位，不修改模型内容。
3. 当前目录的脚本应通过 `bash setup_head_pwm.sh start` 启动。直接输入 `setup_head_pwm.sh start` 找不到命令，是因为当前目录通常不在命令搜索路径中。
4. 用户日志显示 `libzbar0t64` 与 `pyzbar` 已安装，此次无需重复安装二维码库。

终端只粘贴命令内容，不要把代码块标记、`bash` 标记行、`yuting@yuting:... $` 提示符一起粘贴。出现连续的 `>` 提示符时先按Ctrl+C退出未完成输入。

## 腹部CSI的排查顺序

先读当前枚举与启动信息，不修改配置：

```bash
cd /home/yuting/robot_env
./venv/bin/python -c 'from picamera2 import Picamera2; print(Picamera2.global_camera_info())'
cat -n /boot/firmware/config.txt
sudo dmesg | grep -Ei 'ov5647|unicam|i2c|csi'
```

本次用户读取的配置有 `camera_auto_detect=0` 和 `dtoverlay=ov5647`。这是OV5647的手动配置组合，符合 [树莓派官方相机配置说明](https://github.com/raspberrypi/documentation/blob/master/documentation/asciidoc/computers/camera/rpicam_configuration.adoc)。仍需查看其所在条件区段和内核日志，不能仅凭两行判定它已生效或相机硬件正常。

若日志表明驱动已尝试访问OV5647但通信失败，先检查连接。执行 `sudo poweroff`，等系统关闭后断开电源，再检查腹部相机排线两端是否插正、插到底并锁紧；之后重新上电枚举。不要带电插拔。树莓派4使用标为CAMERA的接口，操作依据见 [官方安装说明](https://www.raspberrypi.com/documentation/accessories/camera.html#install-a-raspberry-pi-camera)。通信失败可能来自排线、接触、供电或模块故障，日志本身不能确定哪一项。

只有枚举重新出现真实CSI传感器后，才选择对应的列表位置作为 `ROBOT_KICK_BELLY_DEVICE`。Picamera2的 `camera_num` 使用返回列表的位置，不应只凭内部 `Num` 猜测；见 [Picamera2源码](https://github.com/raspberrypi/picamera2/blob/main/picamera2/picamera2.py)。
