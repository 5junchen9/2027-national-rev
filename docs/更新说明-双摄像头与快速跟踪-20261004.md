# 双摄像头与快速跟踪更新说明

日期：2026-10-04。对应本轮五项反馈。旧交接说明中的 117/127 是历史参数，本轮 handover 默认使用 119/129。

## 已修改

- 启动、按 G 重新开始、腹部接管后的回正位置均为 **119**；低头限位为 **129**。这里的“下限”对应旧交接说明中的 `handover=127`，不是 `bounds` 的较小端点。
- `head_calibration.json` 和 `right_foot_reference.json` 只读取；本轮参数在内存中应用，不改写现场文件。原有方向、机械范围、分辨率、设备和翻转检查保留。需要其他位置时用 `--forward`、`--down-limit`。
- USB 不再强制 MJPG，恢复由驱动选择默认格式，与远古版本的选择方式一致；缓存改为四帧。后台持续读取，只向识别与预览交付最新一帧，避免缓存积压。发布和消费均复制数组，避免后台读帧改变正在显示的图片。
- handover 双摄各自独立采集，默认请求 **30 fps**，原有单摄任务和其他模式的帧率配置保留。启动打印 USB 实际协商格式、分辨率及帧率；窗口 `capture` 是后台读帧频率，`view` 是双摄处理与显示频率。`age` 是后台收到这一帧至显示统计时的时间，不包含传感器曝光和驱动内的等待。
- 颜色筛选使用现有 OpenCV 的 `inRange`，减少整幅图的 Python/NumPy 临时运算。增加完整绿色矩形过滤，保留网球、白缝、泛白球及边缘局部球的现有规则。
- 根据最近移动速度预测短时间内的位置，允许连续加速移动；多个候选优先比较预测位置。预测最长 0.15 秒，连续丢失后停止外推，远处其他绿色目标不能成为自动重新锁定的目标。无法区分时仍显示丢失或多目标，按 R 或 S/B 重新选球。
- 头部滤波由五帧缩短为三帧；持续偏差至少 0.10 秒、至少三帧后调整，按偏差大小移动 1～3 格，正常间隔至少 0.18 秒、反向至少 0.4 秒。小幅跟随的等待默认 0.18 秒；启动复位和腹部接管后的大幅回正仍用原等待时间。球居中或丢失时保持，低头不超过 129。
- `head` 标定入口和固定舵机测试默认位置也改为 119。旧代码目录没有修改。

## 启动命令

重启后仍先手动启动 pigpio，看到 `pigpio ready`：

```bash
bash /home/yuting/robot_env/setup_head_pwm.sh start
```

运行双摄跟踪：

```bash
ROBOT_HEAD_PWM_BACKEND=pigpio ROBOT_KICK_HEAD_DEVICE=/dev/v4l/by-id/usb-lihappe8_Corp._USB_2.0_Camera-video-index0 /home/yuting/robot_env/venv/bin/python /home/yuting/robot_env/main.py handover --run
```

默认已是 `--forward 119 --down-limit 129 --fps 30 --settle 0.18`，不必额外传参数。按 S/B 分别框选头部/腹部球，R 重新搜索，G 回到头部阶段，Q 退出。

如默认格式仍有条纹，先在同一命令前加 `ROBOT_CAMERA_FOURCC=YUYV` 做对照；也支持 `native` 和 `MJPG`。这是显式的运行参数，不修改系统摄像头设置。若 YUYV 协商帧率低，先查询实际支持的模式，不能把请求 30 fps 当成硬件已经达到 30 fps：

```bash
v4l2-ctl --device=/dev/v4l/by-id/usb-lihappe8_Corp._USB_2.0_Camera-video-index0 --list-formats-ext
```

如果加快后头部明显反向抖动，可在运行命令尾部加 `--settle 0.30`。这个参数表示小幅移动后暂停头部识别的时间，需要通过真实舵机验证；腹部采集和预览在等待期间继续运行。

## 已做的本地检查及限制

- 修改前 82 项测试通过；修改后 **90 项测试通过**。覆盖原有网球样图、白衣背景、局部球、脚位参考，新增加速序列、旧位置干扰球、绿色矩形、119/129 限位、短等待保持输出、最新帧所有权、过期帧及采集失败检查。
- 五个运行文件通过 Python 编译检查。测试用伪摄像头和伪舵机，不打开树莓派硬件。
- Windows 上同一真实样图重复 200 次：腹部样图单帧检测约 **3.80 → 1.96 ms**，头部白衣背景样图约 **3.71 → 1.98 ms**。这不是树莓派性能，也不等于摄像头帧率。
- 合成网球在 50 ms 间隔内横向位置依次为 60、80、115、165、230、310 像素：旧版本从第三帧开始失锁，新版本六帧全部识别。该序列证明连续运动预测有效，不能保证突然跨越整幅画面或完全离开视野时继续跟踪。
- 尚未验证：树莓派实际采集/显示帧率、条纹是否消失、真实舵机在短等待下是否稳定、真实快速网球是否持续锁定。头部只有上下控制，横向移动不会由本模式带动身体追球。
- 将 FPS 提高后，先确认腹部取景和紫色参考框仍对应实际右脚位置。若摄像头自动选择的取景模式或视野改变，需重新验证或保存脚位参考；只检查像素尺寸不能证明视野完全相同。

条纹的根因还未由硬件对照确定。本轮移除了与远古版本不同的强制格式，并解决了软件中的读帧等待和跟随限速；没有把“本地测试通过”写成“硬件问题已解决”。Picamera2 的 `queue=False` 会等下一帧，缓冲和队列行为见[官方手册](https://datasheets.raspberrypi.com/camera/picamera2-manual.pdf)。
