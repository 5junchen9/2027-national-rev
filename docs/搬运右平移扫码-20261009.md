# 抱物右平移扫码（2026-10-09）

## 运行顺序

保留原来的颜色识别、腹部接手和H横向对齐。抱取线改为从底部算60%（从顶部算40%），物块上沿到线或高于线后抱起。HOLD_BOX完成后，头部到133，抱物向右平移，每步结束观察1.2秒，最多执行10次平移动作。平移期间复用RouteVision后台读双摄和解码，不等身体动作完成才扫码。固定扫描腹部，精确读到指定目标二维码一次，就在当前身体动作完成后立即执行一次DOWN_BOX。不使用头部码触发，不再比较D/J位置和尺寸；已解码出其他二维码时不会触发。新增：无法解码时，连续3次后台处理的新腹部图像检测到同一边缘部分二维码也放下；中间漏检或候选位置失配则重新计数。部分码由至少两个定位方框，或一个完整定位框加周围至少8个小块纹理判断，不能确认文本一定是action2，仍有误放风险。预览显示edge QR: n/3和候选框。

第10步后仍会检查扫码结果。仍未确认目标才执行一次DOWN_BOX原地放下，然后重复TURN_RIGHT，返回scan_limit。比赛收到此结果后跳过足球和足球后的转向，直接进入头部寻找dance、腹部确认蓝地、音乐跳舞。正常投放成功仍接原来的足球流程。

单独搬运入口使用同样流程，但超限放下、右转后即结束，不自动开始跳舞。

## 动作与角度

新增SIDE_RIGHT_HOLDBOX使用`搬运右平移-测试.dzz`。腿部沿用`右平移.dzz`轨迹，不经过视觉steering()的左右转换；前7个通道保持HOLD_BOX最后一帧的抱物姿态。原动作文件保留。

此前误用了左平移轨迹，用户实测向左；现已改用右平移轨迹。修正后的抱物平衡和实际方向仍需扶护复测。

`carry_exit_right_actions`默认7，表示超限放下后的右转小动作次数，沿用现有大右转的7次约定。没有角度传感器闭环，不能保证恰好90度；现场测量后调整这个次数。单独测试和比赛都读取此字段。
