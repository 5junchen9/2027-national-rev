# 后退独立调试

本版只调后退，不改比赛入口、BACK映射、原后退动作、相机或标定。

## 候选改动和限制

`assets/actions/后退-准备与收尾测试.dzz`：先用600ms进入腿部标准站姿、上肢沿用旧后退姿态；保留旧后退8帧全部24路偏移，每帧100ms（等于旧40ms乘默认行走倍率2.5）；最后用400ms将腿部偏移归零，上肢保持行走姿态。

只解决“缺少准备与收尾”的候选问题。腿部偏移归零指回标准站姿位置，不是绝对零位。未重写左右腿轨迹，不能保证消除动作中失衡或偏航；如果问题发生在中间帧，需要根据实机反馈再调整，不能只追加收尾。

## 同步

将以下两个新增文件复制到树莓派 `/home/yuting/robot_env` 下的对应目录：

- `app/test_backward.py`
- `assets/actions/后退-准备与收尾测试.dzz`

无需同步配置，不覆盖原动作和H/D标定。

## 使用

关闭比赛、其他身体串口控制程序。空手、后方留空，使用防倒扶持；操作者能随时扶稳，避免手指进入关节夹缝。

先离线检查（不会打开相机、GPIO或身体串口）：

```bash
cd /home/yuting/robot_env
venv/bin/python app/test_backward.py
```

逐帧检查：

```bash
venv/bin/python app/test_backward.py --run
```

输入y后握手，1000ms回标准站姿，再等待2秒。每帧前回车继续，输入任意文字后回车停止。逐帧停留可能使单脚支撑姿态更难保持，全程扶持；它只用于观察哪一帧开始异常。

确认逐帧没有碰撞或异常扭转后，再测试连贯单次动作：

```bash
venv/bin/python app/test_backward.py --run --continuous
```

两次输入y确认站姿和单次后退。执行一次即结束，不循环、不接转身。测试程序使用文件中的实际毫秒数，不叠加行走或通用时间倍率。

Ctrl+C只阻止后续发送，不能撤回正在执行的帧。退出只关串口，不自动回站或卸力，人工扶稳后再处理。每次重新运行会先回标准站姿，不要在失衡状态直接重启。

## 回报结果

旧动作对比使用同一程序，额外加 `--old`：

```bash
venv/bin/python app/test_backward.py --old
venv/bin/python app/test_backward.py --old --run
venv/bin/python app/test_backward.py --old --run --continuous
```

旧动作读取原 `后退.dzz`，按当前 `ROBOT_WALK_SCALE` 缩放时长，默认2.5，即每帧100ms；不添加候选的准备和收尾帧。两版都先用1000ms回标准站姿并等待2秒。完整旧动作比较命令可显式设置 `ROBOT_WALK_SCALE=2.5`，使迈步时长与候选一致。每次测试后人工扶稳、复位到同一位置和方向，再运行另一版，不自动连续执行两版。此对比不复现比赛中的后续右转。

逐帧记录“第几帧、哪只脚抬起/拖地、身体向哪侧倒”；连贯动作记录“从机器人自身看左偏/右偏、约偏多少度、后退距离、结束时是否双脚落稳”。最好拍正后方和侧面视频。先单次通过，再人工复位重复测试；不以一次成功认定稳定。
