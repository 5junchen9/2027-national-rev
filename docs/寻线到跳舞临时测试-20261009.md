# 从寻线到跳舞的临时测试

在树莓派 `/home/yuting/robot_env` 目录使用现有比赛环境运行。
机器人放在寻线起点，指定颜色物块位于路线前方；准备足球场和舞区。
本入口跳过 face 扫码、人脸识别和人脸后的固定回程3步。

```bash
cd /home/yuting/robot_env
source venv/bin/activate
python3 competition_line.py --from-line --simulate --color red
python3 competition_line.py --from-line --check
python3 competition_line.py --from-line --run --actions --color red --line-color white
```

从物块附近开始、跳过寻线，使用：

```bash
python3 competition_line.py --from-carry --simulate --color red
python3 competition_line.py --from-carry --run --actions --color red
```

部分二维码无需解出文本，但须有边缘定位框和邻近黑白模块，连续3幅独立检测一致才放下。
头位127找球时，只要稳定识别网球并连续确认，就交给足球模块平移对齐和接近，不要求居中。
看到球时停步确认；连续3帧检测不到球才右转一步重新观察。入口不执行左转或偏边纠正。

`--simulate` 仅打印流程，不打开相机或发送动作。Mock默认走正常投放分支。
`--check` 沿用整场比赛预检，因此仍要求原有人脸模型、语音和其他比赛资源齐全。
实际测试不会预加载人脸模型或预热人脸播报。

正常链：寻线找物块 → 双摄对位抱起 → 抱物右移扫码放下 → 头位127右转搜索，稳定看到球后交给足球模块对齐和带球
→ 右转7次 → 头部寻找dance → 腹部确认蓝地 → 前进1步 → 播放音乐并跳舞。

搬运右移7次仍未确认目标：原地放下 → 同样进入头位127视觉找球 → 带球 → 舞区。
放下后不再固定右转7次；找球最多90秒、30次转向，失败则停止。
配置中的carry_exit_right_actions不再控制比赛转向；足球结束后去舞区仍按after_sport_right_actions执行。
其他错误（如足球阶段失败）停止整条链，不强行继续。

保持正式版计时：配置总期限480秒，但寻线耗时不计入；其余阶段的局部上限保留。
双摄画面尺寸及搬运、足球标定必须匹配，检查通过后才连接身体串口。
真实测试会站立、行走、抱物和跳舞，需要全程防倒保护。
Q、Esc或Ctrl+C退出；已经发送的身体动作不能撤回。
仅寻线并在发现物块时结束，仍使用原 `--run --actions --line-only`。

本地模拟和单元测试不能证明实机投放到位、进球或整机进入舞区。

足球完成条件：腹部接管、看得到球时前进一次UP_LITTLE；动作完成后，
在头位不变的3秒观察窗口内连续5帧、至少0.3秒未检测到球，即按消失规则结束。
不再比较球框大小和远离距离；识别持续漏检也会被算作完成，不能证明进球。
找球仍需颜色/形状检测。优先使用高饱和黄绿色球面，在球面附近补白缝，
保留完整球圆形、出画球圆弧和背景差异筛选；没有高饱和候选时保留暗光/偏白球重找。
