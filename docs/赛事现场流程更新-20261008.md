# 赛事现场流程更新（2026-10-08）

本说明取代10月7日说明中的sber、旧目的地、返回赛道及人脸左转流程。

## 当前顺序

1. 腹部识别face，身体右转1个小转动作，头位124识别姓名/性别，首次有效结果播报；成功后身体左转1次回路线。
2. 腹部识别完整文本left，直接右转3个小转动作。取消原sber后的固定前进。3次沿用此前现场次数，不是软件测得的精确45度。
3. 腹部识别action1，右转4次后直接进入物品搬运，没有固定入口直行。
4. 按指定颜色抱取，抱起后头位125寻找完整文本action2；精确解码确认后按当前投放规则放下。
5. action2同时是足球开始处，投放后头位125直接进入足球；取消原按颜色右转返回以及回程前进一步。
6. 足球完成后仍右转7次，头位120用头部扫描dance；dance改为2次解码确认，其他路标仍3次。
7. 腹部确认蓝色舞区，再执行原音乐和舞蹈。

用户已确认125指“刚抱起就用125扫码”。搬运扫码和后续足球均用125，dance仍120。旧120头位D不会直接当作125参考。

## 识别改动

网球沿用原颜色资料，在内存中放宽自动黄绿色下限30→28、饱和度最多45、亮度最多80，保留圆形/圆弧和背景差异检查。未改现场球标定文件，未取消相机设备与翻转一致性检查。更宽阈值曾导致地板/白衣区域回归失败，已改用通过原回归测试的温和放宽。

二维码在原图、2倍灰度、二值增强失败后，补一次局部对比度增强。路线后台只保留一个解码任务，忙时继续读双摄新画面、不排队旧帧；主流程在解码忙时不发起下一次前进。只有新解码结果参与确认；预览刷新不累计次数。真正掉线或画面过期仍停止动作。解码线程本身无法被安全强行中断，若底层调用永久卡住，退出清理仍可能受影响。

## 原标定与action2

H抱取参考与目的地文本无关，可沿用。换成action2时在内存中弃用旧目的地D；头位改为125也会使旧120头位D无效，不改原文件。继续用此前的`--use-original-drop`即可在无有效action2 D时按旧版下沿57%触发、目标二维码解码确认3次放下。该规则未验证实际物块落点。默认不加此开关仍要求对应action2的D参考。

相机路径/翻转不匹配与光照不是同一问题，不自动换USB设备，也不因颜色阈值放宽而跳过视图检查。

## 必须同步代码和配置

本轮修改的运行文件：

- app/competition_main.py
- app/competition_route.py
- app/competition_qr.py
- app/carry_vision.py
- app/ball_debug.py

同步到树莓派/home/yuting/robot_env下对应位置。前一轮共用相机的competition_identity.py、handover_debug.py也应已同步，避免函数参数版本不一致。

现场config/competition.json合并以下字段，保留其他已调参数：

```json
"factory_qr": "left",
"left_right_actions": 3,
"drop_qr": "action2",
"sport_head_position": 125
```

删除废弃字段after_sber_steps、sber_right_actions、return_right_actions、after_return_steps。action1_right_actions仍4，after_sport_right_actions仍7，dance_head_position仍120。不要覆盖整个config目录或标定JSON。运行仍用全套competition.py --run --actions --color blue --use-original-drop，并沿用现场已核对的双摄和pigpio环境变量。

本地模拟和单元测试不等于实机验证；小转实际角度、暗光识别、足球退出、实际落点和舞区进入均需现场复测。
