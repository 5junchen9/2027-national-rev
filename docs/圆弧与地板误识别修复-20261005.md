# 圆弧与地板误识别修复

## 部署

仅将本次 `app/ball_debug.py` 覆盖到树莓派 `/home/yuting/robot_env/app/ball_debug.py`。

要求沿用上一轮位置锁恢复版的 `app/handover_debug.py` 和多轮头部搜索版的 `app/walk_kick.py`。如果上一轮尚未部署，三个文件一起覆盖。现场config不覆盖，启动命令不变，初始头位129，搜索仍只移动头部。

修改前备份标签 `backup-before-arc-floor-fix-20261005` 指向 `7c95da0`。

## 修改内容

- 贴边候选也必须有圆弧证据。剔除图像边缘3像素内的裁切直边后，拟合可见轮廓。用完整点集和三段轮廓分别拟合，至少65%的点支持同一圆、覆盖至少80度才通过；半径必须在图像尺度范围内。不会只凭三个点认球。
- 完整球沿用原形状检查，不用贴边圆弧筛选替代所有完整球检测。
- 自动黄绿色带排除部分偏黄褐色地面，手动采色沿用用户选定颜色范围。
- 强光亮球面单独提取候选，避免先与地板连成一个颜色区域。新增亮候选必须有颜色线索，且经过原圆形或新增圆弧检查；纯白圆形没有颜色线索时不会作为新球获取，白纸矩形仍拒绝。
- 正常跟踪保留位置和大小约束；自动恢复候选不再受旧框尺寸限制。连续3帧拒绝后，新候选连续3帧位置、尺寸基本一致再接管。恢复后仍等待身体动作稳定确认。
- 如果自动学到错误地板颜色，连续丢失3帧后允许检查另一黄绿/绿色带；手动采色不自动切颜色带。避免尺寸修好了，颜色仍被旧地板锁死。

## 验证与限制

144项本地测试通过，包含旧识别样例、绿色贴边矩形拒绝、四边半球、白纸和无颜色线索白圆拒绝、旧地板大框与错误绿色学习后的恢复，以及双摄交接和头部搜索。

新增两个样例从用户桌面截图中裁出可见相机区域：`tests/fixtures/head_green_floor.png` 和 `tests/fixtures/belly_large_right.png`。前者连续检测后框在球附近而非大片地板；后者可识别右侧裁切大球，并从预置错误地板框恢复。这些截图带界面文字和画框，不能代替原始视频或真实运动验收。

本地检查使用模拟GPIO、摄像头和串口。新增轮廓与拟合计算在树莓派上的处理帧率尚未测量。强遮挡、完全变白且无颜色线索、球与背景连成复杂轮廓仍可能漏检；同色圆形其他物体仍可能误识别。自动恢复只能选视觉候选，不能证明物体身份。
