| 工厂入口 | 腹部扫描 | 直走直到 `action1`，右转约45度 | 进入双摄搬运模块；到物块的距离仍需处理 |
| 搬运 | 指定颜色方块；头腹交接 | 用已验证的新抱起动作；抱住后向右搜目的地码，视觉对准搬运 | 执行一次放下动作 |
| 回到路线 | 按颜色配置的回程右转次数 | 右转恢复路线方向，前进可调次数 | 完成配置动作；方向需现场验证 |

## 3. 细则与调试方向

### 二维码和行走

只在当前阶段匹配对应的完整文本，二维码不作为Python、网址或任意动作执行。连续3帧确认；一旦有目标码候选，先停下来确认，避免前进跨过码。其它内容只显示。每段有步数和时间限制，不一直走。路线后台线程在身体动作期间持续采集并解码双摄，记住连续确认的当前目标路标；动作后读新画面再决定下一动作，旧路标不会触发下一阶段。尚无动作中实时急停。

这版是二维码路标加已有步态，不是连续地面线循迹或全局定位。摄像头没看到目标码时只能在限定步数内沿标定方向前进，超过限制停止。要保持赛道，必须标定单步位移、偏航和各处方向；不能凭程序运行结束声称路线合格。

新比赛入口使用旧项目已有的 `pyzbar` 与系统 `libzbar0`，不依赖OpenCV是否编译QUIRC。路线、比赛搬运和 `--calibrate-carry` 的H/D标定都使用同一个解码函数；旧入口的解码方式不变。后台处理帧率和倾斜二维码识别仍需树莓派验证。

### 45度和90度

既有大右转是7次小右转，用户现场认为约90度。45度暂取4次小右转，不截取DZZ半帧，也不调用旧RIGHT1（它实际重复7次）。配置中逐处独立填写次数，包括不同颜色完成搬运后的回程。4次只是起始估计，必须测量；负载、地面、电量都会影响角度。

### 姓名和性别

用户指定的模型来源是 `/home/yuting/Desktop/robot_legacy`。重新按文件内容核查，`debug_gender.py` 内已有裁剪、RGB预处理、指定 `gender_output` 和男女结果解析；`debug_model.py` 直接加载FairFace ONNX。旧 `Desktop/robot/main_1.py` 和平级 `robot_legacy/app/face_main.py` 包含姓名识别与播报。三个副本的姓名EIM文件哈希相同。

诊断脚本引用的 `FaceDetectorDNN`、`GenderClassifier` 和预处理常量定义仍未找到。这不再作为新入口的阻塞条件：新适配器直接加载已有模型，复用诊断步骤，只补齐加载代码和按作者版本核验的参数。相机、头舵机、姓名适配层和中文语音沿用当前 `robot_env`。同学源码和模型内容保留；2026-10-06修复会补齐EIM文件的所有者执行位。补齐部分是本次适配代码，参数依据见审查文档。

改为检测整个画面，不限定左右位置；多脸时等待，避免读错立牌。姓名和性别连续确认后播报。用户已确认本流程只播报姓名、性别，因此不加载情绪模型。模型准确率、立牌倾斜、光照及语音完整内容需实机验收。头位120是用户估计的指令值，不是已测物理水平角。

### 搬运

头、腹相机在现有搬运模块中同时采集：头部找较远的物块并对准、靠近，腹部接管近处物块并按H标定位置抱取。若两路都看不到物块，目前只搜索头部方向，不继续身体前进。因此，工厂入口至物块的空白直线段尚未实现自动走过；后续可加入有限步数的双摄直线搜索，需要现场确定方向和步数。本次启动修复没有增加这项运动。配置历史键 `factory_qr` 仍保存 `sber`、`carry_qr` 保存 `action1`，键名不代表最新场地名称。

沿用双摄H/D标定文件，不覆盖现场配置。正常 `HOLD_BOX` 已接入用户实测不前摔的 `抱低处物块-减小前倾测试.dzz`，4帧、每帧600ms。正常连播与逐帧停顿不同，仍需确认连续抱起稳定。

抱住后先等待观察；目的地不在头部视野时，比赛入口允许有限次数的抱物右转搜索，每次转完再观察，不盲走。找到完整匹配码后沿用视觉对准和放下位置标定。不得把右前方45—70度直接换算为固定准确转角。没有夹持传感器，放下动作完成不证明物块落在目标区域。

### 舞区与音乐

蓝色背景在搬运区和足球区也可能出现，所以必须先经过足球和 `dance`。蓝地检测分别检查腹部画面近、远两个区域，要求连续确认，拒绝孤立蓝方块。此判据仍只是摄像头视野中的蓝地，不证明双脚或整个机器人已进入区域；现场调ROI、比例和进入后额外步数。不能用“看到一点蓝色”就跳舞。

音乐文件沿用 `assets/music/dance.mp3`，失败时不报告舞蹈成功。第二段旧舞蹈已停用，沿用1/3/4/5段。

### 最少保护

预览不打开身体串口；真实动作需 `--run --actions`。正式启动前检查模型、语音资源、动作文件、搬运和足球标定，减少开走后才发现缺文件。总限480秒，各模块在循环和动作发送前检查期限；同步动作、识别和音频仍可能使检查延迟，Q/Ctrl+C不是硬件急停。抱取、放下、踢球和舞蹈不自动重发，失败停止，不自主猜测完成。

## 4. 实施顺序

1. 新建流程与有限步骤路标扫描，支持无硬件模拟。
2. 给旧搬运和球跟踪增加可选共享机器人连接，旧入口默认不变。
3. 加入同学识别适配器、有限目的地搜索、舞区门槛和音乐检查。
4. 验证顺序、错误码、重复码、丢码、期限、共享资源释放、抱物参数、舞蹈唯一触发。
5. 自动自审结果单独记入 `比赛流程审查与部署-20261005.md`；软件验证和实机验收分开记录。

## 5. 现场验收顺序

先确认模型和依赖 → 双摄无身体动作预览 → 人脸姓名/性别及声音 → 一次小右转角度、4次/7次角度 → face/sber/action1三段 → 各颜色连续抱起和投放 → 每色回程方向 → 球动作与实际进球 → dance识别和舞区确认 → 音乐舞蹈 → 8分钟整轮。

每项记录实际二维码内容、次数、电量、地面、动作前后视频和是否满足任务规则。整轮验收前不宣称“比赛已完成”。
