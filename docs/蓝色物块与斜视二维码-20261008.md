# 蓝色物块与斜视二维码

旧形状检测检查蓝色连通轮廓的长宽比、填充率、凸包及多边形；不是物体类别识别。地面矩形图案可能通过，同色盒子和地面粘连也可能丢失。

本次增加：
- 完整头部蓝色候选至少三条边需有图像边缘支持；近处截断候选保留原跟踪保护。
- 蓝色掩膜粘连时，用独立图像边缘找凸四边形盒面。要求内部至少65%蓝色、与周围Lab外观有差异，限制尺寸和长宽比。
- 寻线入口复用BlockTracker(recover_head=True)的颜色/形状/面积/连续性评分，不再直接取最大色块。后续仍需同一候选三帧确认。

仅二维图像规则仍不能可靠区分“地上一个看起来像盒面的蓝色矩形”和真实盒子，特别是相同颜色、亮度、纹理时。本版不声称解决所有误检；实际帧率和背景区分需现场确认。

二维码：解码内容仍严格匹配action2，新增保留四角，紫色线显示四边形。新D/J分别保存drop_quad/drop_head_quad；H不变。
- 与对应相机参考比较四边相对长度，明显透视变化时不前进/不放下。
- 目标偏离参考中心超过12%画面宽时，允许先小步转向居中；居中后仍透视不匹配就等待，不猜测横移方向。
- 形状匹配后用对边平均长度比例判距离，避免把旋转后的外接矩形当实际二维码边长；仍保留原尺寸90%-120%、中心误差与三帧新解码释放条件。
- 旧D/J没有四角时继续使用旧宽高判定，没有自动生成四角。重新保存D/J才启用新几何检查；标定方向应匹配实际搬运路线的投放姿态。
- 四角无法可靠恢复时，带四角标定不允许前进或放下。该实现不是绝对距离/三维位姿估计，也不会自动推断牌子侧视角对应的横移方向。

同步app目录：carry_vision.py、competition_qr.py、competition_line_main.py，新增qr_geometry.py、blue_block_edges.py。无需修改competition.json，不覆盖现场标定JSON或同学代码。

现场先备份：

```bash
cd /home/yuting/robot_env
cp -n config/carry_dual_reference.json config/carry_dual_reference.before-quad.json
bash setup_head_pwm.sh start
venv/bin/python competition.py --run --calibrate-carry --color blue
```

标定程序不执行身体动作。先按真实抱物姿态将机器人放到实际投放位置，再保存D（腹部）；头部可见时J先定位133，稳定后再次J保存。不要按H，保留抱取标定。仅保存当前真实完整action2二维码，不使用错码或模板漏读。
