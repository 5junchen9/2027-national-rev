# 头部双摄交互调试

## 现场修订：前视117，增加指令低头

本节取代下文旧版按键顺序。根据本轮实机日志，F记录前视117，K方向为增加指令低头；127是交接尝试位置，但检测未通过且旧版本没有保存成功。新版默认前视117、K方向，重复K不清除同方向交接记录，F保留已确认的低头方向。启动仍不驱动，G才执行显示的起始指令。

```bash
cd /home/yuting/robot_env
source venv/bin/activate
export ROBOT_KICK_HEAD_DEVICE=/dev/v4l/by-id/usb-lihappe8_Corp._USB_2.0_Camera-video-index0
python3 main.py head --run
```

点击相机窗口：G执行117；默认步长1，D逐次低头，也可按5后D两次试到127。需要现场再次确认这个球的位置具有重叠视野，而不是把127当成任意距离都能交接。H检测成功可直接S；H提示检测不足时，只有亲眼确认两路实时画面看见同一个球，才按V人工确认，再S保存。V只接受本次H后的当前位置，移动或修改前视/方向会取消待确认记录。自动识别仍需后续优化，不把人工确认冒充检测通过。

保存config/head_calibration.json记录人工/检测确认来源；旧文件先备份。Q退出。没有自动生成“已成功”JSON，也未接入自动运动流程。若前视不准确，用A/D调整后F重新记录；按实际安装的方向设置J/K。下文保留原版背景，但运行默认值和保存规则以本节为准。

本阶段仅调试头部，底盘不动、不连接机器人串口。旧人脸任务实际调用level，指令95，并未记录物理抬头45度的换算。舵机命令不是头部相对地面的实测角度。本工具沿用驱动85..180范围；确认前视与低头方向后，进一步限制为向下20、向上45个指令单位。不能据此宣称物理低头20度已标定。若机构提前到限位，停止调节。

将本轮列出的文件复制到/home/yuting/robot_env对应位置，不复制Windows虚拟环境。

```bash
cd /home/yuting/robot_env
source venv/bin/activate
export ROBOT_KICK_HEAD_DEVICE=/dev/v4l/by-id/usb-lihappe8_Corp._USB_2.0_Camera-video-index0
python3 main.py head --run --start 95
```

窗口需要获得键盘焦点。启动只开双摄，不立即驱动舵机。95只是旧配置参考值，确认能执行该初始指令后按G。不是从舵机当前物理位置读取角度；原舵机没有此读取接口。若旧参考不适用，退出，用已知可用指令替换--start值再运行。

1. G启用头部，A减少/D增加指令。默认每次1；数字1/2/5切换步长。每次移动后等待画面更新。按键只控制头部俯仰BCM27。
2. 调到朝前看门的姿态，按F标记前视位置。观察A/D哪边使头低下，再按J标记“减少=低头”，或K标记“增加=低头”。设置后向下最多20个指令单位；若旧85..180限制更窄，使用更窄范围。
3. 将同一个球放在拟定交接距离，逐步低头，使head和belly都能看见唯一球，按H记录交接指令。需要手动确认两路确为同一个球。若20以内没有重叠，不扩大范围硬找，先调整腹部安装或球的交接距离。
4. S保存config/head_calibration.json；已有文件会先备份。Q/ESC退出，Ctrl+C也可。退出只释放控制，不自动回正。

请返回保存的JSON和两路交接画面，再接入自动“向球接近→逐步低头→腹部接管→头部回前视”流程。当前自动双摄踢球入口没有使用此头部标定文件；不要把原来的固定头姿kick --run当作已支持动态头部。动态头部接入后需重新做球位置标定，旧kick_calibration.json不能直接代表多个头姿。
