# 双摄像头与头部跟踪交接说明

更新日期：2026-10-04。供后续聊天窗口或开发者接手。以下实测结论来自用户贴出的树莓派终端记录；本地检查不能代替硬件测试。

## 现在这一步在测试什么

当前入口是 `main.py handover --run`，机器人身体不运动，不发送走路或踢球串口指令。

测试链路：

1. 启动后，头部复位到标定的持平位置 117。
2. 头部 USB 摄像头识别球，舵机根据球在画面中的上下位置调整。球进入中央区域时保持，丢球时保持。不得看到绿色就按固定时间一路低头。
3. 球接近头腹视野交接区域后，腹部 CSI 摄像头稳定识别并接管，头部回到 117。
4. 腹部继续跟踪球，将球的可见区域与保存的右脚位置参考比较，满足条件后显示 `RIGHT FOOT MATCH`。

此时由人缓慢移动球，模拟机器人走近球。通过这轮测试只能证明静止状态下的跟踪、交接和位置判断；不能证明机器人走动时仍可靠，也不能证明能踢进球门。

## 用户目标与约束

- 在新代码中基于旧功能增加双摄像头踢球，保留旧代码功能。
- 最终流程：头部观察球并随接近过程低头；腹部接管近处球；头部回正看球门；身体通过视觉反馈调整到右脚踢球位置。目前暂不要求射进球门。
- 原头部摄像头保留原有任务；新腹部摄像头用于辅助定位，不用于替代原二维码功能。
- 当前测试用球已换成网球，要求支持绿色、绿白色、荧光绿及球只露出一部分的情况。比赛球的实际规格仍未确认。
- 锁定后不要跳去识别远处其他物体；远球泛白、光照变化和边缘遮挡仍需实测。
- 不加开机启动。Windows 镜像修改后只列出变化文件，由用户自行复制，不打包。
- 保留原始旧代码，不覆盖用户在树莓派上生成的标定文件。

## 已标定参数

树莓派 `config/head_calibration.json`：

- `forward=117`，持平参考。
- `handover=127`，头腹交接姿态。
- `down_sign=1`，命令值增大表示低头。
- `bounds=[85,137]`。
- 这些是舵机命令单位，不是已测量的物理角度。
- 交接由用户目视确认，当时自动形状检测没有通过。

树莓派 `config/right_foot_reference.json` 最近一次贴出的有效内容：

- `version=2`，`method=yellow_green_visible_region`。
- 画面形状 `[480,640]`。
- `visible_patch_box=[0.0390625,0.0,0.4015625,0.51875]`。
- 颜色：`hue=40`、`hue_width=14`、`min_s=55`、`min_v=100`。
- 上边缘截断：`clipped_edges=["top"]`。
- 位置定义是球的可见颜色区域，不是完整球的中心。
- `automatic_kick_enabled=false`。

这份位置参考依赖拍摄方向、球、光照和实际脚位。换球或调整摄像头后需要重新验证。Windows 镜像可能没有用户最新 JSON 和参考图片，不能直接用镜像覆盖它们。

## 本轮已解决与尚未确认

已确认：

- `python3-pigpio` 可从 trixie 安装，但系统没有可直接安装的 `pigpiod` 包；已将驱动编译到项目 `.head_pwm` 目录。
- 启动脚本最初使用 `-l`，所用源码会优先绑定 IPv6 本机地址 `::1`，而客户端连接 IPv4 `127.0.0.1`。增加 `-n 127.0.0.1` 并重启旧进程后，用户得到 `pigpio ready`。
- 用户运行固定 117、持续 10 秒的测试，输出 `Servo 27 set to angle 117 (pigpio)`，随后正常返回终端。
- 本地最近一轮 82 项测试通过，启动脚本 Bash 语法检查通过。

尚未确认：

- 用户没有明确报告固定角度测试后抖动是否消失。
- 最新双摄像头跟踪、交接及 `RIGHT FOOT MATCH` 的现场通过情况未得到完整确认。

## 启动与测试命令

每次树莓派重启后先手动启动驱动：

```bash
bash /home/yuting/robot_env/setup_head_pwm.sh start
```

必须先看到 `pigpio ready`。当前正式参数包含 `-g -t 0 -l -n 127.0.0.1 -x 0x08000000`；使用 PWM 时钟以保留 PCM/I2S 给声卡，GPIO 更新限定到 BCM27。没有创建开机启动服务。

单独确认舵机固定角度是否抖动：

```bash
/home/yuting/robot_env/venv/bin/python /home/yuting/robot_env/hardware/Head.py --run --angle 117 --seconds 10 --backend pigpio
```

启动本轮双摄像头测试：

```bash
ROBOT_HEAD_PWM_BACKEND=pigpio ROBOT_KICK_HEAD_DEVICE=/dev/v4l/by-id/usb-lihappe8_Corp._USB_2.0_Camera-video-index0 /home/yuting/robot_env/venv/bin/python /home/yuting/robot_env/main.py handover --run
```

操作以窗口当前提示为准：`S` 框选头部球，`B` 框选腹部球；拖动框选，Enter 确认，C 取消。`R` 清除锁定重新搜索，`G` 重新进入头部阶段，`Q` 退出。不要用旧版双击操作。

## 本轮通过标准与下一步

1. 固定角度不明显抖动；跟踪时没有频繁反向抽搐。
2. 球上下移动时头部随动，球居中或消失时头部保持；没有固定速度的自动低头过程。
3. 锁定球后不轻易跳去其他绿色物体；远近、局部遮挡及画面边缘有可重复的跟踪表现。
4. 腹部接管后，头部回正到 117。
5. 将球放在已经物理测试过的右脚位置，能稳定出现 `RIGHT FOOT MATCH`；移开后能撤销匹配。

先完成以上验证。若失败，记录是识别丢失、头部随动、交接还是脚位匹配失败，再改对应部分。通过后再接入单步身体动作与视觉反馈，最后接入实际踢球；不要一次把识别、行走、踢球全部打开。
