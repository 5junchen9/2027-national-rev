## 动作流程

稳定看到头部球后，先用已有 SIDE_LEFT/SIDE_RIGHT 对齐，再 UP_LITTLE 前进。腹部开始看见球时暂停前进并等待稳定交接。接管后根据保存的右脚参考框横移或前进；连续五帧位置匹配且球稳定后执行一次 RIGHT_BALL，随后结束，不自动补踢、不判断进门。暂不按球门方向转弯。

一次身体动作完成后，丢弃旧帧、重新确认新画面，再决定下一次动作。多个颜色目标无法区分时暂停，按 S/B 选择球。

连续至少3次不可靠观测且持续0.3秒后开始重找：先原地重新搜索1秒，保留颜色但清除旧位置锁；仍找不到就低头3个指令单位，再观察1秒，最多3次低头，可越过旧137终点；之后仍找不到才执行一次已有前进动作，重新观察，最多2次搜索前进后停止。初始没有看见球、交接双丢球和腹部接管后丢球均适用。通过颜色、形状和位置筛选后，多个候选按区域填充评分最高选择；同分时选面积较大的候选。手动框选仍限制首次定位。找到形状评分至少0.55且稳定5帧的目标即恢复跟踪。评分是区域填充率，不是真实概率。总身体动作最多30次、整段最长120秒。R/G/重新选球会重新开始搜索，不清除本轮总动作计数。

摄像头掉线、读帧失败、分辨率变化会退出，绝不把这些故障当成普通丢球。已开始发送的 DZZ 仍会执行：窗口 Q/Ctrl+C 不是已验证的硬件急停。UP_LITTLE 和 UP 使用同一份 forward.dzz，不是真正小步；物理步幅过大时需要实测的小步动作文件，不能靠软件名推断。

## 树莓派启动

本轮 handover 身体动作的串口固定在 app/handover_debug.py 的 BODY_SERIAL_PORT：

`/dev/serial/by-path/platform-fd500000.pcie-pci-0000:01:00.0-usb-0:1.4:1.0-port0`

不用手动输入，也不读取其他任务的串口配置。换 USB 插口后这条路径可能改变，需要改这个常量。

```bash
cd /home/yuting/robot_env
bash setup_head_pwm.sh start
ROBOT_HEAD_PWM_BACKEND=pigpio \
ROBOT_CAMERA_FOURCC=MJPG \
ROBOT_KICK_HEAD_DEVICE=/dev/v4l/by-id/usb-lihappe8_Corp._USB_2.0_Camera-video-index0 \
ROBOT_KICK_BELLY_DEVICE=0 \
./venv/bin/python main.py handover --run --actions
```

加 --actions 启动时，双摄及标定检查通过后立即连接固定串口，收到 FB 回馈后发送一次站立指令，再让头部回正到129，进入观察和动作流程；不用等到识别球。start_robot() 是独立初始化函数，后续可放入 main()，返回的机器人对象要继续复用并在退出时 close()。不加 --actions 时不连接身体串口、不发送身体站姿。S/B 框选头部/腹部球，Enter 确认，R 清除目标，G 回到头部阶段，Q 退出。Q 只在动作间处理。
