## 流程与遮挡处理

找物块初始头位仍127；腹部确认并抱起后，头位调整到133，执行原配置delivery_right_actions次数的抱物右转，再由头部和腹部同时寻找完整action2。action1后右转3次、抱起后预右转配置、足球和其他任务顺序保持不变。

两路独立解码、跟踪和标定，不平均两路像素坐标。优先使用有投放参考、当前实际完整解码的腹部；腹部不满足时使用头部。头部被物块挡住、二维码被裁切或只有旧框跟踪时，该路不参与身体控制。另一摄像头有稳定完整解码时接手；切换视角重置动作确认，身体动作后两路都重新确认。这里不声称能区分物理遮挡与普通漏读，统一按该路当前不可用处理。

只有某一路有完整解码但没有该路D/J时，该路只辅助转向；居中后等待已标定相机看见目标，不凭未标定视角推算距离、前进或放下。两路均无可靠解码时先停下等待，再按最后可靠视角方向有限转向搜索；不盲走，不因二维码消失放下。仍有40次身体动作、搬运300秒和全赛480秒限制。

## 标定与使用

标定入口不自动站立或抱取。先按此前单独指令站立、等待2秒并执行HOLD_BOX一次，再保持真实抱物姿态，将机器人放到action2旁实际适合放下的位置。先备份现场参考：

```bash
cd /home/yuting/robot_env
cp -n config/carry_dual_reference.json config/carry_dual_reference.before-dual133.json
bash setup_head_pwm.sh start
export ROBOT_HEAD_PWM_BACKEND=pigpio
```

先确认现场真实存在的头部USB路径；若仍是错误的video-index，则临时指定此前已确认存在的video-index0路径，不能照抄不存在的设备：

```bash
export ROBOT_KICK_HEAD_DEVICE=/dev/v4l/by-id/usb-lihappe8_Corp._USB_2.0_Camera-video-index0
venv/bin/python competition.py --run --calibrate-carry --color blue
```

按键：

- H：原腹部物块抱取参考；本次无需重做。
- D：只保存腹部action2投放参考；已有效的腹部D可沿用。
- J：头部133投放参考。第一次按J切换头位到133；画面稳定、完整action2至少5次稳定确认后，再按J保存。
- Q：退出，不执行放下。

D与J必须在同一个实际投放位置、实际抱物姿态下保存，两路尺寸各自归一化。J写入drop_head及drop_head_position=133；D仍写入drop及drop_camera=belly。互不覆盖，保留原H。旧127/125头部D不会自动转成J。若133时头部始终被挡住，无需强行保存J，保留有效腹部D即可运行；此时头部只能辅助找方向，不能独立接近和投放。

预检至少需要有效腹部D或133头部J之一；若希望两路都能独立接近投放，应两份都保存：

```bash
venv/bin/python competition.py --check
```

全赛试跑前，结束标定抱物状态，将机器人和物块恢复比赛起始位置、姿态，再执行：

```bash
venv/bin/python competition.py --run --actions --color blue
```
