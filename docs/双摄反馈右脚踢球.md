# 双摄反馈右脚踢球

2026年10月3日。根据现场目录，开发与部署入口统一为/home/yuting/robot_env。旧Desktop、robot_legacy和此前压缩包保留，本次不增加开机启动。

## 本版行为

默认踢球模式dual：头部原USB寻找一个圆形球和一个矩形或U形门框；每次只执行一个已有转弯、平移或前进动作，之后重新观察。头部球接近标定下沿时才打开腹部CSI；进入近距离阶段后两路相机保持打开，头部继续找门，腹部定位球。对准标定门方向、球进入右脚目标区域且大小合适，连续3帧确认后仅发送一次RIGHT_BALL。

预览为标定需要，一开始同时打开两路相机；不初始化机器人串口或GPIO。双摄模式不自动改变头部角度，标定与运行必须保持同一头部俯仰和站姿。旧固定左脚模式仍可用--mode fixed运行。语音4和整轮中的踢球在新robot_env内默认调用dual，缺少标定时失败退出，不自动退回固定踢球。

不按颜色筛选。不把矩形当圆球，合并同一轮廓内外边缘；多个候选、目标消失、相机失败时不继续发送动作。形状仍可能误认其他圆形/矩形物体，现场先验证画框；本版没有颜色和目标身份模型。只处理前方球与门，不搜索门后方，也不绕到球后方。

## 安装与预览

迁移包robot_env_dual_kick.zip内顶层就是robot_env。先把树莓派现有robot_env完整备份，再在/home/yuting解压新版；没有删除旧版或虚拟环境的命令。旧venv可保留使用，下面的setup会补齐CSI系统包并检查依赖。如果从U盘直接复制，只复制压缩包或robot_env目录，不复制Windows虚拟环境。

```bash
cd /home/yuting
cp -a robot_env "robot_env-before-dual-$(date +%Y%m%d-%H%M%S)"
unzip robot_env_dual_kick.zip
cd /home/yuting/robot_env
bash setup.sh
source venv/bin/activate
python3 main.py check
python3 main.py simulate
python3 main.py kick --mode dual --preview
```

解压遇到同名文件时需选择替换新版代码；备份已经保存。复制包不包含venv或Pi系统配置。setup不创建启动服务，不修改boot配置。Picamera2从apt安装，venv需继承系统包；若旧venv无法import picamera2，不直接覆盖它，另建venv-dual并使用该环境。

```bash
python3 -m venv --system-site-packages venv-dual
source venv-dual/bin/activate
python3 -m pip install -r requirements.txt
```

在config/robot.env单独设置两路设备。头USB设备默认0，可用原摄像头完整/dev/v4l/by-path路径；腹部CSI默认相机索引0，可用rpicam-hello --list-cameras核对。头USB默认上下翻转0，腹部默认none。

```text
ROBOT_KICK_HEAD_DEVICE=0
ROBOT_KICK_HEAD_FLIP=0
ROBOT_KICK_BELLY_DEVICE=0
ROBOT_KICK_BELLY_FLIP=none
ROBOT_KICK_MODE=dual
```

USB和CSI虽然都叫0，但采集后端不同，是两个独立实例，不是同一设备。ROBOT_CAMERA_BACKEND在新版统一为usb供原任务使用；腹部由自己的CSI实例采集，不参与二维码解码。不要通过把全局backend改成csi来做双摄。改变相机节点、翻转、帧率或分辨率后必须重新标定。

## 标定交接与右脚区域

窗口head是头USB，belly是腹部CSI。绿色框表示门候选，黄色框表示球候选；顶部显示候选数量。只有各目标唯一时才能继续。按键在相机窗口获得焦点后操作，大小写均可。

1. 机器人站稳、头部姿态固定。将球放在头部即将看不到、但仍能完整检测的位置，确认腹部也能看到同一个球。按H记录交接位置。两路没有重叠可见区时拒绝记录，需要调整摄像头俯角或交接点，不能盲走跨过不可见区。
2. 保持站姿和头部角度，把球放到已经实测能右脚踢中的正前方位置。该位置应比H时更近；腹部中球的大小与纵向位置应有可测变化。身体正对门，使已知右脚正前方出球方向指向门内。
3. 在belly窗口点击两次，选择球心允许落入的右脚小矩形区域。它是球心允许范围，不是右脚本身的框，也不应覆盖整幅画面。窗口不可随意缩放后按截图坐标猜位置。
4. head里有一个门，belly里有一个球且球心在小区域内，按S保存。保存门中心参考位置、有效击球球大小、区域、两路分辨率和实际近远方向，得到config/kick_calibration.json。失败会打印Not saved原因，不生成虚假标定。
5. 按Q或ESC退出。R清空本次选择。再次S覆盖标定前会保存带时间戳的旧JSON备份。

这个标定只限定可用踢球姿态和画面方向，未完成完整空间几何标定。目标区域不是预先硬编码的右下角，也不猜球走到哪个像素就一定能踢。腹部纵向方向从H位置与击球位置两次观测获得，支持画面纵向方向不同的安装。

## 执行

先确认机器人端口。若/dev/ttyUSB0确实接机器人控制板，可执行：

```bash
export ROBOT_SERIAL_PORT=/dev/ttyUSB0
python3 main.py kick --mode dual --run
```

没有标定，或设备配置/分辨率改变，真实运行会拒绝。初始只开头相机，首个移动决定成立后连接机器人并发送站姿，然后丢弃旧帧、重新确认，才开始移动；达到H位置打开腹部。交接后头部可以不再看到球，但必须持续看到唯一门框；腹部必须持续看到唯一球。

按Q/ESC或Ctrl+C退出。检测缺失15次停止；读取失败立即停止；最多30个反馈动作，时限120秒。旧DZZ整段动作执行期间不能靠此程序中止；每段完成后再观测，不是每个舵机帧实时纠偏。UP_LITTLE仍是完整前进DZZ，大转弯7次不会整组使用，本版用单次TURN_LEFT/RIGHT。若一整步导致越过球或小转弯仍太大，需要实测并增加真正的小步DZZ，不通过改名字伪装小步。

有效击球后会立即结束，不自动补踢；即使串口发送中途报错也不自动重试。日志在logs/dual-kick-时间.jsonl，保存观测、决定和发送记录。RIGHT_BALL完成只说明动作执行完成，本版没有自动验证球是否穿过门，不能宣布比赛得分或保证踢进。

旧固定动作仍保留：

```bash
python3 main.py kick --mode fixed --run
```

这是旧左脚动作，不用双摄。单纯python3 main.py kick只输出计划、不打开相机或串口；有--preview才开相机，有--run才允许机器人动作。
