## 1. 唯一比赛入口和顺序

入口：`competition.py`；顺序定义：`app/competition_route.py`；硬件阶段衔接：`app/competition_main.py`。

| 阶段 | 当前行为 | 切换条件 |
| --- | --- | --- |
| 起步 | 初始化双摄、核对标定画面尺寸；打开一次身体连接、站立一次 | 初始化成功 |
| 园区身份核验 | 腹部边走边寻找完整文本 `face`，单次小步左转后，头位124运行同学FairFace及姓名OCR | 连续确认姓名、性别并完成播报后，单次小步右转回路线 |
| 工厂核验路线 | 腹部寻找 `sber`，再前进1小步、右转3次；寻找 `action1`，右转4次 | 对应二维码连续确认，配置动作完成 |
| 入口直线段 | 先走 `factory_entry_forward_steps` 小步，默认3 | 每步完成并观察新画面；任何读取失败则退出 |
| 指定物块搬运 | 调用 `carry_vision.run`，头部找颜色块并接近；腹部稳定接管，横向对齐且上沿到顶部20%线后抱取 | HOLD_BOX完成后只用头部寻找指定目的地码 |
| 目的地搬运 | 头位120，精确匹配目的地文本；视觉转向、接近、放下 | DOWN_BOX一次执行结束；不证明实际投放到位 |
| 返回路线 | 按颜色配置右转，默认各4次；再前进1步 | 配置动作完成 |
| 足球 | 调用现有双摄行走带球；球连续变小并远离后停止 | 软件远离条件满足；不证明进球 |
| 舞区入口 | 足球后右转7次；头位120，头部寻找 `dance` | 目标码连续确认 |
| 蓝色舞区 | 腹部近、远区域均达到蓝色占比，连续确认后再前进1步 | 蓝地条件满足；不证明整机已进入舞区 |
| 音乐舞蹈 | 播放 `assets/music/dance.mp3`，依次执行DANCE1、3、4、5 | 音乐未提前结束且动作结束 |

扫描阶段只匹配当前目标的完整二维码文本，不访问二维码网址。路标连续确认3帧；舞区连续确认5帧。旧路标不触发下一阶段。各模块共享身体连接，阶段切换时释放原摄像头/头舵机，再交给下一模块。

## 2. 先走几步，再用搬运补足距离

这是本轮用户确认的方式：从 `action1` 右转后，先走少量直线小步，再启动已有视觉搬运。不增加新的空白段扫头前进算法。

在 `config/competition.json` 中调整：

```json
"factory_entry_forward_steps": 3
```

3步只是待测初值；若入口离方块很近，调为0或更小。固定直线段没有物块距离判断，不应为了找不到物块就无限加步。后续搬运保持看见目标才视觉接近、近处丢失有限交接的现有保护。

固定前进及转向，每次动作完成后继续刷新画面，等待 `observe_seconds`（默认1秒）再执行下一次。此等待不改变动作文件播放速度。sber右转已按现场反馈改为3次；action1仍4次，足球后仍7次，各段角度须负载下验证。

其他常用配置：

| 键 | 默认值 | 用途 |
| --- | --- | --- |
| `after_sber_steps` | 1 | sber后直线补偿 |
| `sber_right_actions` / `action1_right_actions` | 3 / 4 | 两个独立转弯次数 |
| `delivery_search_right_actions` | 5 | 抱起后二维码丢失的有限搜索次数 |
| `return_right_actions` | 各颜色4 | 不同颜色投放后的回程转向 |
| `after_return_steps` | 1 | 返回路线后直线补偿 |
| `after_sport_right_actions` | 7 | 足球后朝向舞区 |
| `drop_qr` | 现有微信二维码完整文本 | 搬运目的地；只作为文本匹配 |
| `total_seconds` | 480 | 整场期限 |

自定义 `--config` 文件也需加入 `factory_entry_forward_steps`。运动次数允许0至30；这是错误输入边界，并非30步经过现场验证。

沿用现场双摄设备配置。下列USB路径来自之前部署，运行前应确认仍存在，腹部CSI编号仍为0。

```bash

export ROBOT_HEAD_PWM_BACKEND=pigpio
export ROBOT_CAMERA_FOURCC=MJPG
export ROBOT_KICK_HEAD_DEVICE=/dev/v4l/by-id/usb-lihappe8_Corp._USB_2.0_Camera-video-index0

```

先做无硬件顺序演练，再检查资源：

```bash

venv/bin/python competition.py --check
```

只预览双摄，不打开身体串口：

```bash
venv/bin/python competition.py --run --preview --color blue
```

```bash

```

现场指定颜色可换成 `red`、`yellow`；不提供 `--color` 会在身体启动前询问。标定仍用：


H切123头位，再按H保存腹部横向参考；D切120头位，再按D保存目的地距离参考。先等画面稳定。现场已有正确标定无需重做。Q或Ctrl+C退出后不再发后续动作；同步播放中的动作不能立即撤回，仍需现场硬件停止措施。

预检查失败不会打开身体串口；识别、搬运、足球、舞区或舞蹈失败时整场退出，不跳过任务继续执行。整场480秒及各模块原有限制继续生效；发送前估计剩余时间，但阻塞的硬件操作不是实时定时器。

## 5. 验证与未验收项

本地测试验证路标顺序、颜色对应回程、入口先走后搬、共享连接、阶段失败后禁止后续任务、固定动作间等待、搬运与球阶段现有行为，以及音乐失败处理。模拟只演练分支，不验证相机、动作角度或模型准确率。

赛事足球评分依据实际踢球和进球；当前按用户之前约定保留行走带球，不可将“球远离”当作得分依据。没有夹持或足部位置传感器，动作结束也不能证明抱稳、投放到位或机器人完全进入舞区。

## 7. 人脸前后转向与分散功能差异检查

2026-10-07：`face`确认 → `TURN_LEFT`一次 → 人脸识别及播报 → `TURN_RIGHT`一次 → 寻找`sber`。`TURN_LEFT`对应“左转.dzz”播放一次，`TURN_RIGHT`对应“右转.dzz”播放一次，不使用`LEFT1`或`SIDE_LEFT`横移。识别或播报失败则停止，不执行返回转向或后续任务。一次左转和一次右转不是经测量的精确逆运动，最终方向需要现场确认。

本轮检查以维护目录源代码为依据，未读取树莓派当前文件或运行环境。比较对象是同学的姓名/性别版、当前双摄视觉搬运、当前`handover_debug`行走带球及独立舞蹈，不把旧固定搬运或固定踢球误当作最新视觉版。
