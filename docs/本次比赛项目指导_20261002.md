# 小人形组新规修改建议与项目指导

历史指导副本。2026年10月3日的旧代码验收、USB与CSI角色边界、正式通知核对及模型数据问题，以本目录《旧代码整理与视觉识别使用手册》为准。本文提及的后续功能不是整理版已经实现的功能。

更新日期：2026-10-02。适用于本次陕西赛区现场测试的小人形组。

先修复中文播报，再完成辅助摄像头、防滑抓取与视觉对准，同时验证摔倒检测和自主起身。赛前复用现有动作和控制接口，强化学习作为后续研究项。每项修改先独立测试，再串联比赛流程。

本文件作为本次比赛的技术修改指导。旧《人形机器人自主任务实施方案.md》保留作历史参考；其中投篮、指定五人身份识别及旧场地尺寸不作为本次新规要求。总控仍沿用《机器人语音总控框架规划.md》的单任务执行、完成后回待命、资源清理约定；比赛的五项任务触发与场地衔接方式另需向裁判确认。

## 1 比赛依据与边界

依据用户提供的《陕创赛组〔2026〕7号 关于人形机器人赛道现场测试的通知》及附件3。规则内容仅用于确定任务要求。

- 小人形组两轮，每轮完成五项任务，限时8分钟，最终取两轮最高分；同分比较用时。
- 原始满分210分，按“原始分 ÷ 210 × 60”折算为实物竞技成绩。
- 整机厚度≤30cm、宽度≤30cm、高度≤60cm，电池电压≥7.4V；新增支架与摄像头后重新测量。
- 任务过程中人工干预、机器人脱离场地且不能自主返回、摔倒后不能自主起身继续任务，对应任务/项目失败计0分。
- 10月3日18:00前学校汇总登记材料；10月8日15:00—17:30报到抽签；10月9日9:00—12:00现场测试。最终时间安排以组委会通知为准。

| 任务 | 原始满分 | 新要求与修改重点 |
| --- | ---: | --- |
| 园区身份核验 | 30 | 一男一女两张AI合成人脸图片，标有姓名；识别人脸及性别，完成清晰播报或赛前指定动作。确认是否必须播报姓名、是否须分别响应两张图片。 |
| 工厂身份核验 | 30 | 识别二维码并视觉循迹，通过三个核验点，每点10分；不能仅凭解码成功宣布通过。 |
| 工厂流水线工作 | 60 | 从三个不同颜色物块中识别赛前指定颜色，搬到指定二维码处；错误目标或未完成搬运计0分。 |
| 足球体育运动 | 30 | 识别黄色网球，明显踢球动作将球送入球门垂直投影面得30分；踢中未进门得10分；每轮仅一次机会，球不复位。 |
| 舞蹈娱乐 | 60 | 到指定区10分，自主播放音乐并预设舞蹈30分，赛前指定简单语音交互20分；未到区及分项计分的解释赛前确认。 |

赛前确认二维码实际内容、物块大小和重量、场地图尺寸、球门与起点位置、姓名字体与图片摆放高度、公布指令，以及任务间是否允许搬移和重新摆放机器人。现有示意图不足以直接确定这些参数。

## 3 中文播报修正

### 问题定位

用户确认故障为扬声器反复读“Chinese letter”，不是屏幕字体乱码。项目旧参考程序 `参考/运动控制/robot_face_recognition.py` 使用 `pyttsx3` 自动选择声音，没有确认已选普通话；当前 `face_main.py` 和 `voice_main.py` 主要播放预录音频。尚未连接树莓派确认故障程序，必须核对实际启动路径。

### 本次软件改动

- 新增根目录 `chinese_speech.py`，复用部署依赖中已有的 `espeak-ng` 和 `mplayer`。
- 动态文字先检查普通话音库，明确指定 `cmn`；兼容旧版 `zh` / `zh-cmn`。没有普通话时报告失败，禁止默认英文回退。
- 文字通过标准输入发送，并明确指定UTF-8；先生成临时WAV，再由项目已有播放器播放，结束后清理临时文件。
- `face_main.py` 优先使用已有姓名录音；录音缺失或播放失败时合成中文。播报失败返回 `False`，不再把识别成功误报为整项完成。
- 旧参考程序的 `VoiceBroadcast.speak()` 改为调用同一工具；修改前已备份。该参考程序含另一种运动控制示例，不能为测试声音而启动完整程序。
- 保持当前总控的就绪提示、歌曲、舞蹈和已有录音播放方式。未改变动作、串口参数或比赛任务逻辑。

普通话合成属于基础离线方案，音色偏机械，姓名多音字和生僻字需要现场核对。若基础方案音质不足，再替换为轻量神经中文模型；当前未下载或安装 `sherpa-onnx` 模型。

### 部署与听音验证

在Windows项目根目录运行 `./sync_raspberry_pi.ps1`，将 `raspberry_pi/home/yuting/Desktop` 内的更新文件复制到树莓派 `/home/yuting/Desktop`。无需覆盖或移动树莓派自己的 `venv`。

```bash
cd /home/yuting/Desktop
# 第一条检查不打开摄像头、串口，也不播放声音。
python3 chinese_speech.py --check

# 确认系统具有普通话合成器和项目播放器。
command -v espeak-ng
command -v mplayer
espeak-ng --voices
# 仅在工具缺失时安装；当前部署说明已经包含这两个工具。
sudo apt install espeak-ng mplayer

# 下列测试只播报声音，不控制机器人，也不调整声卡设置。
python3 chinese_speech.py "你好，我是小童，中文播报测试。"
python3 chinese_speech.py "张三同学，欢迎你。"
python3 chinese_speech.py "这张图片的性别标签为男性。"

# 仅生成文件；使用新文件名，避免覆盖已有录音。
python3 chinese_speech.py "你好，我是小童。" --output /tmp/robot-chinese-test.wav
mplayer /tmp/robot-chinese-test.wav

# 语速默认150，可现场调整。
ROBOT_TTS_SPEED=130 python3 chinese_speech.py "中文播报测试。"
```

其他本项目脚本动态播报中文时统一使用：

```python
from chinese_speech import speak_chinese
success = speak_chinese("张三同学，欢迎你。")
```

若模块位于 `b31/2`，需先将项目根目录加入导入路径。部署包还包含修正后的 `参考/运动控制/robot_face_recognition.py`，但不作为比赛启动入口。若实机运行的是其他目录中的旧脚本，需修正那个实际入口的播报调用；仅复制工具不会改变其他程序的发音器。没有声音时沿用项目已经验证的声卡设置排查，不在测试工具中自动改系统音频配置。

### 验证范围

Windows侧检查普通话选择、UTF-8完整传输、录音优先、播放失败回退、无普通话拒绝英文回退、临时文件清理，并编译变更代码。模拟合成器检查只能验证调用和失败处理，不能证明树莓派实际发音正常；树莓派音库、扬声器效果和实际启动脚本仍需现场验证。

## 4 姿态传感器与自主起身

近期推荐将支持3.3V逻辑的六轴姿态模块接树莓派，先做倒向检测与起身调度。传感器刚性固定在躯干，上电静止校准轴向和零偏，结合加速度与角速度估算姿态；采样频率和判定持续时间现场标定。

| 模块端子 | 树莓派物理针脚 | 用途 |
| --- | --- | --- |
| VCC | 1，3.3V | 仅适用于明确支持3.3V供电的模块 |
| GND | 6 | 共地 |
| SDA | 3，GPIO2 | I2C数据 |
| SCL | 5，GPIO3 | I2C时钟 |

先核对扩展板占用与模块上拉电压，不能将5V信号接到树莓派GPIO。可选MPU-6050类模块；具体模块的稳压、供电及接口电平以实物说明为准。

当前动作表没有前倒、后倒起身动作。需要制作针对本机的起身动作，并验证侧倒处理。流程为“检测倒向 → 停止继续发送普通任务帧 → 起身 → 确认站稳 → 重新定位目标”。加传感器不等于自动保持平衡；不能一倾斜就随意失能或强发站立姿态。

动作播放当前有阻塞等待。需要持续采集姿态，并在帧间及等待过程中检查中止条件；所有运动命令仍由同一个串口控制者发送，不能另开线程直接抢写。弯腰、舞蹈和起身动作须使用相应状态的判断条件，避免误判。真正实时平衡补偿后续优先评估STM32侧实现。

## 5 方块抓取与搬运

机械修改先做薄硅胶或橡胶接触垫，必要时加小托边承重。核对爪口宽度、接触面平行度、抓取高度、闭合力度和负载；不能只靠增加舵机力度解决打滑。

软件优先复用 `b31/2/findbox.py` 的颜色识别和现有抱箱动作。把 `carry_main.py` 的“抱起 → 固定走三次 → 松开”改为“指定颜色 → 检测和小步对准 → 抓取 → 确认抓住 → 找目标二维码 → 放置”。目标颜色由赛前公布信息设置，不能固定为旧颜色。

抓取后确认方块随夹爪抬起；方块离开原画面不代表抓取成功。若摄像头无法观察夹持状态，再考虑接触开关。抓取失败、目标丢失和找码失败必须超时退出；需要重试时限制次数，停止条件不能依赖人工扶正。

## 6 合成人脸图片与姓名OCR

当前 `face.eim` 只识别五位预训练人员，不能直接识别比赛中的新合成图片。保留人脸定位，分别新增比赛图片男/女标签分类和姓名文字识别，不将读姓名变成五人身份匹配。

优先评估轻量中文PP-OCR，只在姓名区域运行。两张图片同时出现时按版面位置关联人脸与姓名，多帧一致才播报或执行指定动作，防止错配和重复响应。训练与验证要覆盖合成图片、打印反光、倾斜及场地光照；标签和模型未经验证不得宣称识别成功。

姓名需核对多音字。赛前确认是否必须播报姓名，以及规定动作是否可替代姓名播报；可在完成必需识别后执行指定动作，避免未确认的附加要求拖延整项。

## 7 胸前下方辅助摄像头

推荐保留头部相机，加一只USB近地面相机。头部负责人脸、姓名和远处二维码；辅助相机负责近处方块、网球、地面路线与边界。4B只有一个原生CSI接口，新增USB相机更便于复用现有OpenCV/V4L2读取方式。

先临时固定可调支架，向前下方观察；以脚尖前区域和夹持接触点可见为准。验证站立、弯腰、抱箱三个姿态，尤其检查抱起方块后的遮挡。正中位置遮挡严重时再考虑下胸侧方，避免支架影响手臂动作、重心和起身。

当前 `RobotEye` 只使用一个设备，且固定翻转图像。双摄需分别设置设备与图像方向，使用 `/dev/v4l/by-path/` 等稳定路径，并确认选中实际视频节点。先按640×480、15fps测试，根据任务启用所需相机和模型；不把两个画面直接当成已标定的双目测距系统。

辅助相机用于踢球时，先完成网球和球门方向对准，再触发一次明确踢球动作。不得循环重踢，不能把行走推球算作踢球。

## 8 强化学习与后续安排

4B可评估运行电脑上训练好的小策略模型。当前限制包括机器人动力学模型、关节状态反馈、舵机迟滞和持续控制接口，不能仅凭模型推理速度判断可用。

本次赛前使用预设动作、视觉纠偏和姿态检测。赛后再测完整控制周期，建立模型并开展仿真训练与实机迁移。强化学习不会自动弥补夹爪打滑、摄像头盲区或中文发音器配置错误。

## 9 实施记录与下一步

- 已完成的软件准备：中文播报工具、录音回退调用、旧参考发音器替换、独立自检和部署同步入口。
- 仍待实机确认：故障脚本实际路径、普通话音库、音量和音质；其余硬件与比赛任务改造均未实施。
- 下一步先运行第3节的独立中文测试；通过后再测试当前人脸任务录音及缺录音回退。不要为听音测试启动会运动的旧参考程序。
