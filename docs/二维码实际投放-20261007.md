## 参考与决策

继续使用 `config/carry_dual_reference.json` 中已有D数据：`drop`保存归一化框的x、y、宽、高，`drop_head_position`必须为120。已有正确120头位D可直接沿用，不重做H。

程序同时比较当前二维码与D参考：

1. 远处保持原转向规则，横向对准后执行一次UP_HOLDBOX，动作结束后再观察1.2秒。
2. 当前宽、高分别达到D参考90%至120%时，进入投放确认。横向、纵向中心与参考各相差不超过画面宽/高6%。
3. 宽高变化比例显著不一致时等待，避免斜拍或错误框被当成距离变化。
4. 到位还需连续3个新画面精确解码到唯一目标二维码，才执行一次DOWN_BOX。模板跟踪允许用于原有观察与接近，但不能累计放下确认；漏读会重置确认。
5. 任一边超过参考120%则停止后续动作，不自主后退或强制放下。位置不符则等待，不继续凭旧下沿盲走。
6. 没有有效D时，单独搬运在打开摄像头/身体前拒绝运行；比赛资源检查在整场身体启动前报告缺D。不再回退到“二维码下沿57%就放下”。

90%–120%和中心6%是初版视觉容差，需要现场验证。它不是实际厘米的误差界限。投放参考的物理位置来自现场标定，并假设同一相机、分辨率、头位、二维码实体、近似相同朝向及抱物姿态。相机移动、明显斜拍、身体姿态变化都可能导致等待或停止。

## 没有有效D时只补D

将机器人在抱物姿态下稳定放在这样的站位：从这里执行现有DOWN_BOX，物块应落在裁判规定的目标区域、二维码附近。考虑放下动作把物块放在身体前方的偏移；不要把机器人脚的位置或相机位置当作物块落点。

只启动头部与相机预览，不打开身体串口：

```bash
cd /home/yuting/robot_env
venv/bin/python competition.py --run --calibrate-carry --color blue
```

- 第一次按D切到120头位；等稳定、完整目标二维码在画面内且解码稳定5帧。
- 再按D保存投放参考；必须是真实解码，不能只有模板跟踪，二维码需与画面边缘留出距离。
- 按Q退出。不按H，已有H抱取参考保留。相机配置、目标文本和画面尺寸须与旧参考一致；不匹配时D拒绝保存，保留原H和整份参考。

D保存的是该站位的二维码视觉尺度，程序不能代替你确认这个站位对应正确落点。原D在129头位不能用于120头位，只有这种不匹配或无D时需要补D。

然后逐条运行：

```bash
venv/bin/python competition.py --check
venv/bin/python main.py carry --mode visual --run --actions --color blue \
  --target-qr 'http://weixin.qq.com/r/TDu9pY3EztCxrcnG925e'
venv/bin/python competition.py --run --actions --color blue
```

Q/Ctrl+C不等于硬件急停，不能撤回已发出的动作。仍保留300秒、40次身体动作及整场480秒限制。抱物右转动作的实机稳定问题本轮未修复，不因投放条件更新而额外覆盖动作文件。
