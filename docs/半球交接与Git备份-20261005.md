## 修改内容

1. 靠近图像边缘的球使用可见圆弧判断，不要求完整圆。排除图像截断的直边后拟合圆，至少需要约60度的可见弧、足够点数且拟合误差合理。圆弧不足时仍可走原整球形状筛选。边缘矩形背景不因被截断而直接当成球。
2. 通过圆弧验证的部分球，填充评分门槛使用0.40；完整球仍0.55。只放宽边缘圆弧候选，不全局降低门槛。评分仍不是识别概率。
3. 腹部交接使用连续5次有效识别，再确认3帧；不要求包围框已经静止。半球进画面时大小变化允许继续确认。
4. 确认交接的几帧暂停头部追球，避免低头动作把交接计数清零。
5. 腹部已经看见球但位置不稳定时，身体等待，不进入丢球搜索。身体动作仍要求目标位置稳定，交接宽松不意味着立即行走。

初始头位129、取消137终点、按最高形状评分选球保持。丢球找球只动头部，不增加身体搜索旋转或搜索前进。保留原30次身体动作/120秒保护、相机与串口故障退出。搬运代码不改。

## 替换与使用

只复制 app/ball_debug.py、app/handover_debug.py、app/walk_kick.py 到树莓派 /home/yuting/robot_env/app。启动命令不变。不要覆盖 config，也不需要把本地 .git 拖到树莓派。

```bash
cd /home/yuting/robot_env
bash setup_head_pwm.sh start
ROBOT_HEAD_PWM_BACKEND=pigpio \
ROBOT_CAMERA_FOURCC=MJPG \
ROBOT_KICK_HEAD_DEVICE=/dev/v4l/by-id/usb-lihappe8_Corp._USB_2.0_Camera-video-index0 \
ROBOT_KICK_BELLY_DEVICE=0 \
./venv/bin/python main.py handover --run
```

先用无 --actions 的头部流程，移动球经过交接区。显示 partial ball arc 表示可见圆弧被接受；seen 是连续识别次数，stable 是位置/大小稳定次数。seen 可以先满足交接，stable 尚未满足时身体仍等待。确认后再加 --actions 启用原行走带球调试。

假设球始终在至少一个摄像头里，不等于一定能识别：可见部分过小、强光完全失去颜色、与背景粘连或圆弧被遮挡，仍可能无法可靠判断。没有加入新的白球恢复或无限搜索功能。
